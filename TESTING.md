# Проверка обновлений EduForge AI

Откройте http://localhost:3000 и войдите своим аккаунтом. После обновления используйте Ctrl+F5.

1. **Материалы.** Создайте материал или сгенерируйте через AI. Проверьте заголовки, списки, цитаты, таблицы. Вставьте блок кода, выберите язык, скопируйте код. Загрузите PNG/JPEG/WebP, выберите изображение и задайте подпись, размер, расположение. Сохраните и откройте снова.
2. **AI-иллюстрации.** В редакторе раскройте соответствующий пункт, введите описание и запустите генерацию. Картинка сначала появляется в предпросмотре; вставка в документ — отдельная кнопка. Реальный запрос оплачивается вашим API-проектом и требует доступа к модели изображений.
3. **Группы.** Откройте группу, создайте приглашение, скопируйте ссылку. В другом браузере студент вводит имя и фамилию. В группе обновите заявки и одобрите запись. Повторная заявка с тем же именем не создаёт дубль. Закройте или замените ссылку и проверьте старую.
4. **Профиль.** Добавьте аватар, имя, описание и дисциплины. HTML рекомендует CSS/JavaScript, Python — алгоритмы/анализ данных. Своя дисциплина добавляется через поле поиска. В библиотеке включите «По моим дисциплинам».
5. **Модерация.** Отправьте материал/тест на публикацию. До одобрения новая версия не появляется в библиотеке. Администратор ermek.zhubataev@gmail.com открывает «Аккаунты», ниже — заявки на модерацию: просмотр, одобрение или отклонение с причиной. Предыдущая одобренная версия остаётся доступной, пока новая проверяется. Проверка содержания ручная, с учётом учебного контекста.
6. **Копии.** Другим аккаунтом добавьте опубликованный материал/тест. Появится «Уже добавлено». Автор изменяет и повторно публикует, администратор одобряет. В вашей копии появится обновление: сравните текущий и новый текст, затем обновите. Если вы редактировали материал, ваши правки сохранятся отдельным материалом; текущая версия теста тоже сохраняется отдельно. Изображения копируются самостоятельно. Для старых копий, созданных до этой функции, связи нет.
7. **Задания.** Создайте Python-задание, укажите максимальный балл и проверочные примеры, отправьте ссылку студенту. «Запустить» использует введённые входные данные; «Отправить» проверяет скрытые примеры и считает баллы. Для HTML/CSS работает безопасный предпросмотр; оценку по рубрике ставит преподаватель. Дизайн принимает PNG/JPEG, 3D — GLB со встроенными ресурсами; можно указать HTTPS-ссылку на Tinkercad/SketchUp. GLB вращается в браузере. Нажатие на изображение добавляет точку комментария; сохраните отзыв вместе с оценкой.
8. **Сессии.** Пройдите один тест двумя студентами: порядок вопросов/вариантов может различаться, оценка учитывает идентификаторы. Переключите вкладку, выйдите из полноэкранного режима, отключите и верните сеть. В журнале преподавателя появляются события. Они не доказывают списывание автоматически.
9. **Восстановление.** «Забыли пароль?» отправляет одноразовую ссылку на 30 минут, после смены пароля старые сессии завершаются. Пока SMTP не заполнен, отправка письма недоступна. Google-аккаунт восстанавливается через Google.

## Локальные настройки

Секреты заполняйте только в `.local/settings.json`, не отправляйте их в чат или Git. Можно добавить поля:

```json
{
  "AI__ImageModel": "gpt-image-2.5-sunburst",
  "Smtp__Host": "smtp.gmail.com",
  "Smtp__Port": "587",
  "Smtp__From": "адрес отправителя",
  "Smtp__User": "адрес отправителя",
  "Smtp__Password": "пароль приложения почтового провайдера"
}
```

Это пример дополнительных полей, а не замена существующего файла. Для Gmail нужен пароль приложения при включённой двухэтапной аутентификации. После заполнения перезапустите API. Номер телефона пока не используется.

Для Python должны работать Docker Desktop и подготовленный образ:

```powershell
docker pull python:3.13-alpine
```

Код запускается без сети и без доступа к файлам компьютера, с ограничениями 8 секунд, 128 МБ и двух одновременных запусков. При недоступной среде работа не получает ошибочный ноль за инфраструктурный сбой.

Интерфейс обращается к API через адрес сайта. `API_INTERNAL_URL` в окружении frontend задаёт внутренний адрес API при сборке/старте разработки; локальное значение — `http://localhost:5080`. При размещении настройте адрес backend, HTTPS, Google redirect URI, резервные копии PostgreSQL и SMTP. Для существующей базы добавлены миграции, пользовательские записи не сбрасывались.

## Контролируемая генерация тестов — 11 ноября 2026 года

1. Создайте и сохраните материал с несколькими текстовыми блоками. Откройте новый тест и выберите материал: контроль оснований и покрытия включается автоматически. Для старого теста включите его вручную.
2. В панели «Учебные цели» добавьте конкретные проверяемые результаты обучения. Нажмите «Подтвердить и сохранить цели». Цели общие для тестов этого материала; изменения списка защищены от сохранения поверх другой версии.
3. В настройках AI задайте типы, количество, сложность и общий балл. Сгенерируйте вопросы. Проверьте у каждого цель, цитату и объяснение; отметьте «Я проверил формулировку, правильный ответ и его основание». Можно добавить основания к ручным вопросам без AI.
4. В таблице покрытия проверьте число вопросов, проверенных вопросов и баллы по целям. Непокрытая цель выделяется. Один вопрос относится к одной основной цели, чтобы баллы не учитывались дважды.
5. Сохраните тест. Пока цели не подтверждены, вопросы не проверены или покрытие неполное, API не разрешит публикацию и создание новой сессии в контролируемом режиме. Черновик можно сохранять для продолжения работы.
6. Измените исходный материал, сохранив его. В тесте нажмите «Обновить» в панели целей либо откройте тест заново. Изменённые/удалённые блоки вызывают предупреждения и сравнение прежнего и текущего текста. Подтвердите цели по новой версии, обновите основание либо перегенерируйте только нужный вопрос. Другие вопросы остаются в черновике.
7. Добавьте новую цель: её нужно покрыть вопросом. Измените формулировку существующей цели: связанные вопросы нужно проверить заново. Изменение текста, вариантов ответа, баллов или объяснения в редакторе снимает отметку проверки.
8. Созданная до правок сессия сохраняет прежние вопросы, ответы и баллы. История оценивания не пересчитывается по изменённому уроку.

Редактор сохраняет устойчивые идентификаторы верхнеуровневых блоков. Изменение только выделения жирным не меняет текстовую ревизию; изменение отступов Python учитывается. Деление и объединение блоков может потребовать повторной привязки. У старого материала при первом редактировании без сохранённых идентификаторов возможен консервативный пересмотр нескольких связей.

Автоматическая проверка цитаты подтверждает наличие текста, но не логическую правильность ответа. Неучтённые смысловые зависимости между разделами требуют общей проверки теста преподавателем. Режим обычного теста остаётся доступным и не требует оснований или покрытия. При копировании публичного теста частные фрагменты исходного материала не передаются; для контроля нужно привязать вопросы к собственному материалу.

Миграция AddControlledGeneration добавляет таблицы MaterialRevisions/LearningPlans и поля контроля теста. Применяется штатным запуском API при включённом Database:ApplyMigrations; данные не сбрасываются. В рамках разработки действующая PostgreSQL-база не запускалась и не изменялась.

Проверки: 64 backend-теста без Docker и 3 frontend-теста; проверка типов; браузерный сценарий на отдельной SQLite-базе с имитацией AI, включая редактирование источника и выборочную перегенерацию. Платный запрос к AI в этой проверке не выполнялся. Для диплома отдельно провести сравнительный эксперимент с экспертной оценкой и замером времени.

## Источники и история генераций — 12 ноября 2026 года

1. В новом материале выберите генерацию по источникам. Загрузите PDF с текстовым слоем, DOCX, TXT или Markdown и выберите нужные разделы. Сканы без текстового слоя требуют предварительного распознавания вне приложения. Изображения из файлов не извлекаются.
2. Сгенерируйте и сохраните урок. Откройте паспорт генерации и основания: цитаты должны соответствовать выбранным разделам. После изменения текста блока и сохранения его исходное основание получает предупреждение о правках.
3. На странице «Эксперименты» выберите генерацию. При наличии реальной экспертной оценки укажите оценки, время подготовки и число исправленных вопросов. Неизвестные значения оставьте пустыми. Экспортируйте CSV.
4. Проверьте предупреждения о качестве в редакторе теста. Они помогают найти формальные проблемы, но не подтверждают правильность ответа.

Файлы источников ограничены 10 МБ. Для одного запроса можно выбрать до 8 источников, 60 разделов и 50 тысяч символов. Источники и история принадлежат преподавателю; публичные копии не получают частные документы и паспорта оригинала. Исходный результат генерации хранится отдельно от последующих правок.

Итог проверки: 77 backend-тестов, включая Docker, и 4 frontend-теста прошли; production-сборка и проверка TypeScript успешны. Браузерный сценарий с имитацией AI проверил загрузку источника, генерацию, сохранение без ложного признака несохранённых правок, паспорт, предупреждение после редактирования, экспертную форму и CSV, включая мобильный экран. Тестовые оценки существуют только в отдельной тестовой базе.

В локальной PostgreSQL создана резервная копия перед обновлением; применены AddControlledGeneration и AddSourceDocumentsAndGenerationHistory. Реальная загрузка источника прошла. Реальная генерация остановилась на ответе провайдера expired_secret_key: необходимо обновить AI__ApiKey в `.local/settings.json` и повторить проверку. Ключ в переписку не отправлять. Успешное взаимодействие новых сценариев с реальным AI пока не подтверждено.

Сравнительный пилот подготовлен в [experiments/README.md](experiments/README.md). Его результаты не заполнены; нужны реальные запуски и независимая экспертная оценка.

## Скриншоты и разметка — 17 ноября 2026 года

1. Обновите страницу сайта. Откройте материал и нажмите «Место для скриншота». В красном блоке опишите, какой шаг нужно показать. При AI-генерации инструкций по программам такие места также предлагаются автоматически.
2. Нажмите «Вставить скриншот» в блоке либо вставьте/перетащите файл туда. Можно загрузить отдельное изображение кнопкой «Загрузить скриншот», вставить его из буфера в редактор или перетащить файл в содержание. Поддерживаются PNG, JPEG и WebP до 5 МБ.
3. На изображении нажмите «Редактировать скриншот». Выберите прямоугольник, круг/овал или стрелку и цвет. Протяните фигуру по нужной области. Добавьте пояснение каждому номеру, например «Инструмент Прямоугольник».
4. Нажмите «Подпись из пояснений» либо заполните контекст и выберите «Создать подпись через AI». Для AI передаются скриншот с разметкой и ваши пояснения; проверьте результат. Текст под изображением можно исправить вручную.
5. Нажмите «Сохранить скриншот», затем «Сохранить материал». После повторного открытия фигуры остаются редактируемыми: можно удалить выделение и нарисовать другое, не накладывая новые фигуры на старые. Щелчок по изображению открывает увеличенный просмотр.

Ограничения редактора: до 30 выделений; пять цветов; при сохранении длинная сторона уменьшается до 2400 пикселей, исходник хранится отдельно. Изображения свыше 40 мегапикселей нужно предварительно уменьшить. Для внешних изображений по URL сначала загрузите файл на сайт, чтобы использовать разметку. В этой версии нет обрезки, перемещения готовых фигур или автоматического определения инструмента без проверки преподавателем.

Проверено: 79 backend-тестов, включая Docker; 5 frontend-тестов; TypeScript и production-сборка. Браузерная проверка на отдельной базе с имитацией AI прошла замену заглушки, разные фигуры/цвета, генерацию подписи, сохранение, повторное открытие и удаление выделений, увеличение и мобильный экран. Дополнительно реальная AI-подпись успешно получена через обычный вход QA-аккаунта на собственном тестовом изображении. Обновлённый ключ принят для этого запроса; полная сравнительная проверка генерации уроков и тестов остаётся отдельной задачей.

## Предложение целей и аудитория теста — 17 ноября 2026 года

В тесте выберите материал, включите контроль целей и нажмите «Предложить цели с AI». Появится редактируемый черновик целей по фактическому содержанию урока. Проверьте его и нажмите «Подтвердить и сохранить цели». Предложения не заменяют сохранённые цели автоматически; повторное предложение требует подтверждения замены списка в редакторе. Ошибка AI сохраняет текущие поля. Изменение материала или целей во время запроса отклоняет устаревший результат.

Генерация вопросов в обоих режимах, включая выборочную замену вопроса, получает текущий уровень/язык материала и исходные педагогические пожелания из его собственной сохранённой генерации. Например, «для детей 6–10 лет» теперь передаётся явно. В AI-настройках теста показаны наследуемые условия и есть поле «Пожелания к тесту» для уточнения возраста, длины формулировок и терминологии. Эти пожелания относятся к текущему запросу и фиксируются в его истории; это не отдельная сохраняемая настройка теста. При расхождении педагогических условий пожелания к тесту имеют приоритет, но не позволяют добавить знания вне урока или отключить проверки оснований.

Если материал создан вручную, не связан с историей генерации или скопирован из общей библиотеки, исходные частные пожелания автора не восстанавливаются и не передаются. Возраст в таком случае укажите в пожеланиях к тесту. Публичные копии не раскрывают частную историю. Передача возраста — инструкция модели, а не гарантия возрастной уместности: результат проверяет преподаватель.

Проверено: 85 backend-тестов, 5 frontend-тестов, TypeScript, production-сборка и строгий UI-аудит. tests/learning-browser.cjs на отдельной базе проверяет предложение, ручную правку и подтверждение целей, отказ от замены, сохранность списка после ошибки, передачу пожеланий в запрос теста и мобильный экран. Реальный AI в собственном QA-аккаунте создал короткий урок для детей 6–10 лет, предложил 3 цели и сгенерировал 1 контролируемый вопрос; наличие возрастных пожеланий в параметрах этой генерации проверено. Публикации и студенческие сессии для проверки не создавались. Миграция базы для изменения не требуется.

## Основания, Markdown, удаление и режимы доступа — 17 ноября 2026 года

- Основание каждого ответа первоначально свёрнуто. Нажатие на треугольник/заголовок раскрывает цель, цитаты и объяснение; статус проверки остаётся виден в заголовке. Сворачивание не снимает проверки и не меняет готовность теста.
- В материале **выделение** отображается жирным, без буквальных Markdown-маркеров. В формулировках, вариантах, эталонах и AI-объяснениях двойные звёздочки очищаются. Код, оператор Python ** и точные цитаты оснований сохраняются. Для старых документов очистка выполняется при отображении/редактировании; история генераций и снимки проведённых сессий не переписываются.
- В окнах материала и теста есть отдельные кнопки удаления с подтверждением. Удаление закрывает публикацию и ссылку. Тесты, связанные с удаляемым материалом, остаются без связи с уроком и контроля оснований — об этом предупреждает подтверждение. Сессии, результаты и чужие уже созданные копии сохраняются.

В сохранённом материале/тесте откройте блок «Кто может открыть…». Выберите режим и нажмите «Сохранить доступ»:

1. «Частный» — только владелец; старая ссылка отзывается.
2. «По ссылке» — только вошедшие преподаватели со ссылкой. Нет в каталоге/фильтрах общей библиотеки и обычных маршрутах копирования. Просмотр теста не содержит isCorrect, modelAnswer, оснований или истории AI. Это просмотр, не прохождение: для прохождения используются сессии.
3. «Публичный» — общая библиотека преподавателей после модерации. Общая библиотека сохраняет существующее поведение копирования тестов с ключами ответов для коллег; просмотр по ссылке остаётся без ключей.

Доступ относится к сохранённому снимку. После правок нажмите «Обновить версию по ссылке» или «Обновить публикацию». Публичная новая версия ожидает модерации; до её одобрения доступна прежняя одобренная версия, если она существовала. Закрытие доступа отменяет ожидающие заявки; устаревшая заявка не должна повторно открыть материал. Повторное открытие доступа после частного режима создаёт новую ссылку. У уже скачанных/скопированных данных отозвать доступ невозможно.
