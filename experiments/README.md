# Пилот генерации: подготовка и сбор данных

Тема диплома: «Интеллектуальная система автоматической генерации учебных и тестовых материалов».

## Что уже подготовлено

Приложение сохраняет паспорта обычной и контролируемой генерации, параметры, снимок входного материала, исходный результат, длительность и доступные показатели токенов. Экран «История генераций» позволяет ввести оценки и выгрузить CSV. Неизмеренные значения остаются пустыми.

В fixtures находятся четыре авторских учебных примера: Python, HTML, CSS и требования к 3D-модели. Они предназначены для технического пилота. Это не учебники и не экспертный эталон; для исследования их нужно проверить и при необходимости заменить материалами преподавателя. Источники для итогового диплома оформляются отдельно.

## Безопасный просмотр плана

Из корня проекта:

```powershell
python experiments/run_pilot.py
python experiments/run_pilot.py --case python-loops
```

Без --execute скрипт показывает только план. Он не обращается к API, не создаёт материалы и не расходует AI-квоту. Проверка плана выполнена при разработке.

## Запуск после настройки API

Должны работать PostgreSQL и API проекта, а AI-ключ должен быть действующим. Вход выполняется обычным email/паролем преподавателя; Google-пароль для этого не подходит. Для пилота можно использовать отдельный аккаунт с обычной регистрацией в приложении. Администраторские полномочия не требуются.

```powershell
python experiments/run_pilot.py --execute --case python-loops --series "Python loops pilot 1"
```

Скрипт интерактивно запрашивает email и скрыто вводимый пароль. Для автоматизированного запуска допускаются переменные EDUFORGE_PILOT_EMAIL и EDUFORGE_PILOT_PASSWORD. Не записывайте пароль в аргументы команды, исследовательские таблицы или репозиторий.

Один пример и один повтор означают два AI-запроса: обычная и контролируемая генерация по одному материалу, по четыре вопроса и 20 баллов. Полный набор из четырёх примеров — восемь запросов за повтор. --repeats допускает 1–3 повтора. Перед началом проверьте доступную квоту провайдера; реальные запросы тарифицируются им.

Создаются личные материалы и черновики тестов. Они не публикуются и не назначаются студентам автоматически. Порядок режимов чередуется по примерам и повторам. При ограничении частоты скрипт ждёт одну минуту и повторяет запрос, не более двух повторных попыток. Если произошла ошибка, уже сохранённые результаты остаются в истории. Повторный запуск создаёт новую серию объектов; используйте понятное уникальное имя серии.

## Что измерять

1. Время генерации берётся из паспорта. Оно включает вызов провайдера и проверки сервера, но не труд преподавателя.
2. Полное время подготовки измеряет преподаватель: от запуска до готового проверенного теста, включая чтение, исправления и повторные запросы.
3. В форме оценки вводятся предметная корректность, понятность и соответствие материалу/целям по шкале 1–5. До просмотра ответов согласуйте значения шкалы: 1 — существенные недостатки, 3 — требуется заметная доработка, 5 — замечаний по выбранному критерию не выявлено. Промежуточные оценки описать в методике.
4. Отдельно записываются число исправленных или заменённых вопросов и причины. Это не то же самое, что число ошибок: один вопрос может содержать несколько ошибок.
5. Для вопросного анализа используйте шаблон question-review-template.csv. Поля фактической правильности и поддержки материалом заполняются экспертами, а не вторым AI.
6. При исследовании обновлений заранее внесите исправление факта, удаление фрагмента и изменение только оформления. Зафиксируйте, какие вопросы действительно требуют пересмотра; затем сопоставьте их с предупреждениями системы. Изменение отступов Python считается изменением содержания кода.

Покрытие целей измеряется по подтверждённым связям. Совпадение цитаты подтверждает существование текста, но не логическую выводимость ответа. Эвристические предупреждения о похожих вопросах и вариантах не являются экспертным заключением.

## Как сравнивать

Используйте одинаковые материалы, ограничения, базовую модель и сопоставимые условия. Модель и шаблон должны быть указаны в паспортах. Повторяемость условий не гарантирует дословно одинаковые ответы генеративной модели.

Экспертам желательно представлять результаты без указания режима и в случайном порядке. Для небольшого пилота приводите исходные количества, медианы, диапазоны и примеры ошибок. Вопросы одного материала и повторные генерации не следует считать независимыми участниками исследования.

Сравнение проверяет совокупный рабочий процесс. Чтобы отделить эффект явных целей от проверки связей и сопровождения версий, понадобится дополнительное абляционное сравнение. Текущий скрипт его автоматически не выполняет.

Исследование точности генерации и времени подготовки само по себе не доказывает улучшение успеваемости. Педагогический эксперимент со студентами требует отдельного плана.

## Текущее состояние проверки

12 ноября 2026 года миграции применены к PostgreSQL после резервного копирования. Реальный тест загрузил и извлёк учебный текст через обычный тестовый аккаунт, но генерация остановилась на ответе провайдера expired_secret_key. Успешные реальные генерации в этой проверке не получены. Пользователь планирует обновить AI__ApiKey позже.

Интеграционные проверки и браузерный сценарий генерации с имитацией AI выполнены на отдельной SQLite-базе. Введённые там оценки синтетические, в действующей PostgreSQL-базе они не создавались и исследовательскими результатами не являются. Реальную парную генерацию и экспертную оценку нужно выполнить после обновления ключа.
